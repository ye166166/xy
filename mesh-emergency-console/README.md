# Mesh应急通讯控制台

基于 **M5Stack Cardputer-Adv**（ESP32-S3） + **Cap LoRa-1262**（SX1262 LoRa + ATGM336H GNSS）的离线 Mesh 应急通讯终端。通过 LoRa 无线电在设备组网内实现文字聊天、坐标互传、紧急求救，全部数据本地保存，无需任何基站与网络。

## 功能一览

- **文字通讯**：键盘输入中/英文消息，经 LoRa 组网收发；每条消息标注发送设备、时间、信号强度
- **位置系统**：读取 GNSS 实时经纬度；一键（fn+L）或晃动设备发送坐标；收到的坐标在消息流展示
- **紧急求救**：fn+S 触发，持续循环广播求救帧（自动携带实时坐标）；其余设备红色高亮弹窗 + 扬声器警报，直到人工确认（Enter）消除
- **组网设备管理**：5 秒心跳广播自动发现同频段终端，显示在线/离线与信号强度（含 16 点动态波形）；可修改本机名称
- **AES 加密**：AES-128-CBC 简易加密，密钥不一致的设备只能看到空白报文，无法读取正文
- **历史记录**：聊天记录自动落 SD 卡（`/mesh/log.txt`），开机自动恢复，支持上下翻阅
- **扩展功能**：航点记录/回发（fn+P 保存）、射频参数设置面板（频率/功率/扩频因子）、陀螺仪倾斜滚动

## 界面与按键

| 按键 | 功能 |
|------|------|
| 常规按键 | 聊天界面输入文字 |
| Enter | 发送消息 / 确认 / 编辑设置项 |
| fn + [ / ] | 上 / 下（聊天滚动、列表选择） |
| fn + B | 聊天跳到底部 |
| fn + 1..5 | 聊天 / 设备 / 状态 / 航点 / 设置 |
| fn + S | 开始 / 停止紧急求救广播 |
| fn + L | 立即发送本机定位 |
| fn + P | 保存当前坐标为航点 |
| fn + A | 取消设置编辑 |
| 晃动设备 | 快捷发送本机位置 |
| 前后倾斜设备 | 上下滚动消息列表 |
| 求救弹窗时 Enter | 确认并消除警报 |

> 说明：Cardputer 键盘为物理 QWERTY，文本输入为 ASCII；接收端可正常显示 UTF-8 中文。方向键场景以 `fn+[/]` 替代（键盘无独立方向键）。

## 工程结构

```
mesh-emergency-console/
├── platformio.ini       # 构建配置（M5Cardputer + RadioLib）
├── include/config.h     # 全部可调参数：射频/引脚/组网/体感/求救
└── src/
    ├── main.cpp         # 主循环：键盘、陀螺仪、求救、LoRa 常驻收发
    ├── radio.h/.cpp     # SX1262 收发封装 + RF 开关 + AES 加解密
    ├── gnss.h/.cpp      # NMEA 解析（RMC/GGA）
    ├── mesh.h/.cpp      # 组网协议：帧编解码、设备表、心跳、求救
    ├── store.h/.cpp     # SD 卡历史日志与航点
    └── ui.h/.cpp        # 深色科技风界面（五屏 + SOS 遮罩）
```

## 编译 / 烧录

```bash
cd mesh-emergency-console
pio run                     # 编译
pio run -t upload           # 烧录（自动识别 /dev/cu.usbmodem1101）

```

## 硬件接线（Cardputer-Adv EXT 14P 总线）

| 功能 | 引脚 |
|------|------|
| LoRa NSS / IRQ / RST / BUSY | G5 / G4 / G3 / G6 |
| SPI（与 SD 共用） SCK/MOSI/MISO | G40 / G14 / G39 |
| SD 卡 CS | G12 |
| GNSS UART（RX / TX） | G15 / G13 @115200 |
| RF 天线开关（PI4IOE5V6408） | I2C 0x43，P0 置高（M5Unified 驱动） |

## 重要注意事项

1. **天线**：LoRa 模块未装天线切勿上电，否则可能永久损坏射频芯片。
2. **频段法规**：默认 868.0 MHz（欧盟 ISM）。Cap LoRa-1262 支持 868~923MHz，请在合规频段按当地法规使用，可用设置面板调整。
3. **距离参数**：扩频因子 SF 默认 7（快），可调至 12 换取更远距离但速率骤降（SF12 单包约 4 秒）。
4. **加密一致性**：同组设备需设置相同通讯密钥（设置 → 通讯密钥），否则无法读取正文。
5. **定位**：GNSS 为内置陶瓷天线，请在开阔地带首次定位，冷启动约 23 秒。

## 设备互通硬性规则（必读）

> 多台设备互通，**必须保证所有终端以下参数完全一致**，否则无法解析消息：

| 参数 | 位置 | 说明 |
|------|------|------|
| **频段**（频率 MHz） | 设置 → 频率 | 频率不一致 → 无法收到对方信号 |
| **信道**（同步字 0x00~0xFF） | 设置 → 信道 | 信道不一致 → 解调失败，如同静默 |
| **通讯密钥** | 设置 → 通讯密钥 | 密钥不一致 → 只能收到空白报文（帧头/设备号/求救标识仍可见） |

- **参数一致**：正常收发文字、坐标、求救，设备列表互见。
- **参数不一致**：
  - 频段/信道不同 → 物理层收不到对方任何帧；
  - 仅密钥不同 → 能看到设备存在与求救告警，但正文显示为 `<加密消息>`，无法读取。
- **单机可用性**：单台设备（无论参数如何）均可完整体验全部界面与功能（聊天输入、设置、航点、求救广播、本地状态），但无法与参数不同的其他终端通信。

> 排查互通问题时，先在每台设备的「状态」界面（fn+3）或串口心跳日志核对 `rf=频段/SF/信道 key=开/关` 三项是否一致。
